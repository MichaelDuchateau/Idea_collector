01Tech Stack Recommendation

Given cross-platform desktop, local SQLite, and a small team — here is the recommended stack and why.

Tauri + React + TypeScript + SQLite

Tauri gives you a native Mac and Windows app using your system's built-in WebView. React handles the UI. SQLite runs embedded — no server, no install, just a file. This stack is significantly lighter than Electron (10–20MB vs 150MB+), ships a proper native binary, and the JS/React frontend means rich UI is straightforward.

Full Stack Breakdown

LayerTechnologyReason
App shellTauri 2.0Rust core, native Mac/Windows binary, tiny footprint, secure IPC bridge
UI frameworkReact 18 + TypeScriptComponent model ideal for pipeline views, scorecards, and charts
StylingTailwind CSSRapid, consistent design tokens across all views
DatabaseSQLite via tauri-plugin-sqlSingle file, zero server, fast, well-understood schema
ORM / queriesRaw SQL + typed wrappersFull control, easy to read schema, no magic
Markdown parsinggray-matter + markedgray-matter extracts YAML frontmatter; marked renders body
ChartsRechartsReact-native, composable, good funnel + bar + scatter support
File dialogsTauri dialog pluginNative OS file picker for .md import
Build / packageTauri bundlerProduces .dmg (Mac) and .msi/.exe (Windows) automatically
Why not Electron? Electron bundles a full Chromium + Node runtime per app — typically 150–300MB. Tauri uses the OS's native WebView (WebKit on Mac, WebView2 on Windows), resulting in a 5–20MB binary. For a focused internal tool, Tauri is the better fit.

The computed weighted score for any idea is a SQL view, not stored — it recalculates live from scores × criteria.weight. This means changing criterion weights instantly re-ranks all ideas without a migration.

03Markdown Import & YAML Frontmatter

Ideas can be authored externally in any markdown editor and imported via a file picker or folder watch. YAML frontmatter maps to database columns.

Expected .md File Format

--- (YAML frontmatter block) --- title: "AI-Powered Customer Support Bot" category: "Digital / AI" owner: "Sarah Chen" stage: "screening" status: "active" horizon: "H1" tags: ["automation", "customer-experience", "AI"] created: 2026-03-15 --- (end frontmatter) --- # Body: plain markdown rendered in the idea detail view ## Problem Customers wait 4+ hours for support responses during peak periods... ## Proposed Solution Deploy an LLM-powered first-response bot trained on our knowledge base... ## Open Questions - What's the escalation path for complex issues? - How do we handle sentiment detection?

Import Logic

📂

Single file or batch folder import

User opens native file dialog — selects one .md or a whole folder. All valid files are queued for import with a preview/confirm step.

🔍

gray-matter parses frontmatter

YAML block is extracted and mapped to schema columns. Unknown fields are stored in a meta JSON column — nothing is dropped.

🔁

Duplicate detection by title + source_file

Re-importing the same file offers Update / Skip / Create New — so you can keep markdown as the source of truth and re-sync.

🗂️

Raw markdown preserved

The original .md text is stored in raw_markdown so ideas can be exported back to .md at any time without data loss.

Scorecard Features

⚙️

Admin: Configure Criteria & Weights

Any team member can open Settings → Scorecard and add, rename, reorder, or reweight criteria. Weights auto-normalize to 100%. Changes take effect immediately across all ideas.

🎚️

Per-Criterion Scoring with Notes

Each criterion gets a 0–100 slider plus an optional rationale text field. Notes are stored per-score so the reasoning is auditable.

📊

Live Ranking on Pipeline View

All ideas in the same stage are ranked by weighted score. The rank updates instantly as scores are entered or weights change.

🚦

Threshold Bands (configurable)

Set score thresholds: e.g. ≥75 = Advance (green), 50–74 = Develop Further (amber), <50 = Park/Kill (red). Shown as colour bands in all list and pipeline views.

📋

Unscored vs Scored State

Ideas without scores are clearly marked "Not Yet Scored". The pipeline view can filter to show only scored or only unscored ideas to manage review workload.

05Core Application Views

Five main screens. Each maps to a key workflow in the innovation pipeline.

🗃️

Ideas List / Table View

All ideas in a sortable, filterable table. Columns: Title, Stage, Status, Score, Owner, Horizon, Updated. Quick-filter by stage, status, category, score band. Click to open detail.

🔭

Pipeline / Funnel Board

Kanban-style columns for each pipeline stage. Ideas appear as cards showing title, score badge, and horizon. Drag-and-drop to move ideas between stages (logs to activity_log). Filter by score band.

📄

Idea Detail View

Full idea page: rendered markdown body, metadata panel (stage, owner, tags), scoring panel (all criteria with sliders + notes), activity log, and status controls.

📈

Reports & Charts Dashboard

Funnel chart (idea counts by stage), score distribution histogram, horizon breakdown (H1/H2/H3 pie), top-10 ranked ideas, and category breakdown. All live from the SQLite database.

⚙️

Settings

Scorecard criteria editor (add/edit/reorder/reweight), score threshold configuration, user name setup, database backup/restore, and help section (your existing explorer content).

07Key Open Decisions

A few design choices to confirm before building begins. These affect the schema and UI significantly.

DecisionOptionsRecommendation
Multi-user scoring Single scorer per idea vs. multiple scorers averaged Confirm — Schema supports multi-scorer; UI can show average or individual scores. Start with single scorer, add averaging later.
Score history Overwrite scores vs. keep full score history per idea Keep history — Current schema stores every score entry with timestamp. Trend over time is valuable.
Gate approval Score threshold auto-advances ideas vs. manual stage moves only Manual — Stage moves should always be intentional human decisions. Score is a recommendation, not automation.
Markdown authoring In-app markdown editor vs. import-only Confirm — Import-only is simpler. An in-app editor (e.g. CodeMirror) adds scope but keeps workflow inside the app.
Export format CSV, PDF report, Excel, back to .md Start with CSV + .md — CSV for data, .md for round-trip fidelity. PDF/Excel in Phase 4+.

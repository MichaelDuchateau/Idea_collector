Pipeline — User Guide

Manage your team's innovation pipeline: collect ideas, score them together, track progress through stages, and report on your portfolio.

Overview Team Setup Ideas Scoring Pipeline Board Import Obsidian Reports Settings Backup FAQ

1 Overview

Pipeline is a local-first desktop app for small innovation teams (2–10 people). Each person runs their own copy. There is no server — your ideas live in a SQLite database on your Mac or PC.

👥
Multi-person model: Because everyone has their own database, collaboration happens through shared scoring (enter a colleague's name to score on their behalf), markdown import (share .md files via a shared folder or Git), or Obsidian sync (pull from a shared vault).

2 Setting Up for Your Team

Because Pipeline is local-first, there are three collaboration patterns. Choose the one that fits your team.

🗂 Shared folder

Drop idea .md files into a shared folder (Dropbox, OneDrive, SharePoint). Each person imports from it periodically.

📓 Obsidian vault

Keep a shared Obsidian vault (via Obsidian Sync or iCloud). Ideas written in /Pipeline/ are pulled into the app automatically.

🔢 One person's database

One person acts as the "pipeline owner" and runs the database. Others score on their behalf (enter their name in the scorer field).

First launch checklist

  1. Open the app. The onboarding screen asks for your name — this becomes your scorer identity. Every score you submit is tagged with this name.
  2. Review the default scorecard criteria (Strategic Fit, Market Attractiveness, Technical Feasibility, Financial Potential, Resource Requirements). Edit them in Settings → Scorecard if needed.
  3. Set your score band thresholds in Settings → Thresholds. Default: Green ≥ 75, Amber ≥ 50.
  4. If using Obsidian, enter your API details in Settings → Obsidian.
⚠️
Scorer names must match exactly across the team. If Alice enters her name as "Alice" and someone else scores on her behalf as "alice" (lowercase), the app treats them as different scorers. Agree on a naming convention before you start scoring.

Scoring as a team

When multiple people score the same idea, the app averages their scores per criterion. The weighted score on an idea's badge is the mean across all scorers.

To score on behalf of a colleague (e.g. after a workshop where scores were recorded on paper):

  1. Open the idea → Scores tab → Score this idea.
  2. Change the scorer name field to the colleague's name before submitting.
  3. Their scores are saved separately and averaged in alongside everyone else's.
💡
The Score Breakdown tab on any idea shows each criterion broken into individual scorer values so you can see disagreements at a glance.

4 Scoring

Open any idea and click the Scores tab. There are two panels: Score this idea (your input) and Breakdown (everyone's scores).

How the weighted score is calculated

Each criterion has a weight (0–1). Your score on a criterion (0–100) is multiplied by its weight, then the total is summed. Scores from multiple people are averaged per criterion first, then weighted.

Strategic Fit (w=0.30)
80
Market Attract. (w=0.25)
65
Tech Feasibility (w=0.20)
70
Financial Pot. (w=0.15)
55
Resource Req. (w=0.10)
40

Example: (80×0.30)+(65×0.25)+(70×0.20)+(55×0.15)+(40×0.10) = 67.5 → Amber

Score bands

BandDefault rangeMeaning
Green≥ 75Strong candidate — prioritise for next stage
Amber50–74Potential with conditions — needs more work or data
Red< 50Weak on current criteria — reconsider or kill
Unscored—No scores submitted yet

Change the threshold values in Settings → Thresholds.

Customising the scorecard

Go to Settings → Scorecard to add, rename, reweight, or deactivate criteria. Deactivated criteria are excluded from score calculations but their existing scores are preserved. Weights do not need to sum to 1 — the app normalises automatically.

⚠️
If you change the scorecard after ideas have been scored, existing scores are not changed. The weighted score will be recalculated using the new weights on the next load. All team members should use the same scorecard. Share your criteria definitions out-of-band (e.g. paste them into a shared doc) so everyone is scoring on the same basis.

6 Importing Ideas from Markdown

Click the Import button in the top bar. You can import a single file, multiple files, or an entire folder (scanned recursively for .md files).

Frontmatter format

The importer reads YAML frontmatter at the top of each file. All fields are optional — if title is missing it is inferred from the first # Heading in the body, or from the filename.

---
title: My Idea Title
stage: screening          # collection | screening | development | gate | build
status: active            # draft | active | parked | killed | launched
horizon: H2               # H1 | H2 | H3
category: Product
owner: Alex
tags: [mobile, ai]
created: 2024-03-15
---

Idea body text goes here. Full **markdown** is supported.

Import preview

Before anything is written to the database you see a preview list of all parsed ideas. Review titles, stages, and scores before confirming. Any parsing errors are shown inline.

Duplicate handling

If an idea with the same source_file path already exists, the importer skips it (shows as skipped in the result). To update an existing imported idea, edit it directly in the app.

👥
Team tip: Keep idea markdown files in a shared folder (Dropbox, OneDrive, a Git repo). When a teammate writes a new idea, you import it into your local database. You can then score it independently and compare with colleagues by reading each other's score exports.

7 Obsidian Integration

If your team uses Obsidian, Pipeline can pull ideas directly from a dedicated folder in your vault using the Local REST API community plugin.

Setup (one time per person)

  1. In Obsidian: install the Local REST API community plugin, enable it, and copy your API key from its settings pane.
  2. In Pipeline: go to Settings → Obsidian. Enter the API URL (default: http://localhost:27123), paste your API key, and set the vault folder name (default: Pipeline).
  3. Click Test connection — it should turn green.
  4. Click Sync now or set an auto-sync interval (in seconds; 0 = manual only).
⚠️
Sync is one-way: Obsidian → Pipeline. Changes you make inside the app are not written back to your vault. An idea imported from Obsidian shows a banner on its detail page as a reminder.

How it works

On each sync the app lists all .md files inside /Pipeline/, fetches the ones that are new or updated (matched on vault path), parses their frontmatter identically to the file importer, and upserts into the database.

👥
Team tip: Use a shared vault (Obsidian Sync, iCloud, or Git + obsidian-git plugin) so the whole team writes ideas into the same /Pipeline/ folder. Each person syncs into their own local Pipeline database and scores independently.

10 Backup & Restore

Your entire database — ideas, scores, activity log, and settings — lives in a single SQLite file. Back it up regularly.

Backing up

  1. Go to Settings → Backup.
  2. Click Backup database… and choose where to save the .db file.
  3. Store it somewhere safe — a cloud folder, external drive, or alongside your idea markdown files.

Restoring

  1. Go to Settings → Backup.
  2. Click Restore from backup… and select your .db backup file.
  3. Confirm the warning — this overwrites your current data.
  4. Restart the app for the restored database to take effect.
⚠️
Restore replaces all current data. Any ideas, scores, or settings added since the backup was taken will be lost. Make a fresh backup before restoring if you are unsure.
👥
Transferring a database to a colleague: Back up your .db file and share it. They can restore it on their machine to get a copy of your full pipeline — including all scores and activity history. They will need to update their name in Settings → General before scoring.

11 Frequently Asked Questions

Can the whole team share one database in real time?

Not currently. Pipeline uses a local SQLite file — real-time multi-user sync would require a server. The recommended workaround is the shared Obsidian vault pattern for idea capture, with each person maintaining their own scoring database.

What happens if two people score an idea with the same name?

The app enforces one score per person per criterion per idea. If the same name submits a score twice for the same criterion, the second submission overwrites the first. This is intentional — it allows people to revise their scores.

How do I delete an idea?

Open the idea → the delete option is in the idea detail view. Deleting an idea removes all its scores and activity log entries permanently.

The Obsidian connection test fails

Check that: (1) Obsidian is open, (2) the Local REST API plugin is enabled, (3) the API URL matches exactly (including the port number), and (4) your API key is correct. The plugin generates a new key each time it is reinstalled.

Can I change the scorer name on existing scores?

Not through the UI. Scores are stored with the name you entered at the time. If you need to reassign scores, they can be edited directly in the SQLite database with a tool like TablePlus or DB Browser for SQLite.

Where is the database file?

Go to Settings → Backup and click Show path. On macOS it is typically ~/Library/Application Support/com.yourorg.pipeline/pipeline.db.

How do I build a Windows installer from macOS?

Use the GitHub Actions CI workflow included in the repository — it builds .dmg, .msi, and .exe installers on each push to main. See the .github/workflows/build.yml file.
